## 阶段 1｜从"AI 视频生成器"改为"知识编译层"

**时间**：2026-10-30 11:22 – 11:38

**阶段目标**
确定这个作品到底是什么。最初的设想是"输入一句话，输出一条科普视频"。

**当时的做法**
把两个赛题文件逐条拆解，先锁定赛道与红线，再反推产品形态。

- 赛道定为**赛题 5「内容创作与自媒体」**（对应原文"短视频脚本与分镜""科普物料成套生成"）
- 逐条提取交付要求：4 件材料、命名规则、体积上限、哈希校验、提交后不得改动

**关键决策：不生成视频**

理由来自一次自我否决。原方案"输入 → 生成视频"有三个硬伤：

1. 5 天内做不到可用的视频生成，只能调第三方接口，那就成了纯套壳
2. 比赛红线要求内容准确，视频一旦生成错就无法逐帧校对
3. 用户本身已经在用 Opus 手工做视频，工具的价值不在"再生成一遍"

于是把产品重新定义为**编译层**：不执行程序，但没人说编译器是套壳。
产物从"视频"改成"可直接交给任何视频工具执行的制作规格"。

**被否决的输出**

| 否决的方案 | 否决理由 |
| --- | --- |
| 首页做成对话输入框 | 评委打开第一眼就会归类为套壳，架构再好也来不及解释 |
| 「假装接入 Opus」的按钮 | 一旦被追问"这是刚才生成的吗"，怎么答都掉分 |
| 只输出一段提示词 | 没有结构化中间态，等于把 LLM 的活原样转包 |

## 阶段 2｜概念图与分镜推导算法落地

**时间**：2026-10-30 11:38 – 12:12

**阶段目标**
把"输入一句困惑 → 抽象成概念"这句话变成可运行的代码。

**当时的做法**

1. 手写 7 条概念种子库（抗生素疗程、T1/T2 弛豫、k 空间、PET-CT、赌徒心理、熬夜、CT 辐射），每条 = 5～6 个概念节点 + 因果边 + 旁白
2. 写分镜推导：对概念图做**深度分层拓扑排序**，按深度分层排出镜头顺序，切三幕
3. 写 6 条确定性检查规则
4. 搭六步界面：输入 → 概念图 → 视觉风格 → 分镜与检查 → 交接包 → 作品档案

**技术选型上的两次否决**

| 否决的方案 | 否决理由 |
| --- | --- |
| Tailwind CSS | 脚手架生成的是 `@tailwindcss/turbopack` + Next 16，属于前沿组合，评审本地装依赖时出错风险高。改为手写 CSS，零构建插件依赖 |
| `next/font/google` 在线字体 | 构建时需要联网，评审断网就跑不起来。改为系统字体栈 |
| 纯前端 localStorage 存档案 | 评委一定会按 F5。刷新就没了，等于自证是演示玩具。改为服务端文件持久化 |

**关键设计：镜头时长由旁白字数推导**

第一版是平均分配，结果 66 秒 8 个镜头，每镜 8 秒，语速只有 2.7 字/秒，读起来拖沓。
改成"话说得多就给更多时间"，再整体拉伸到目标时长，并满足单镜 2～9 秒的上下限。

## 阶段 3｜接入 DeepSeek，并发现种子库的分类错误

**时间**：2026-10-30 12:14 – 12:29

**阶段目标**
让未收录的题目也能跑，同时验证模型这一层到底能不能用。

**当时的做法**

1. 先写评测脚本 `scripts/eval-model.mjs`，10 道题分三区（影像 6 / 通用 3 / 争议 1）
2. 再接模型。顺序很重要：**先有量尺，再看效果**

**第一次评测就暴露致命问题**

问「为什么核磁共振要做那么久」，系统返回：

> 氢质子自旋 → 射频激励 → T1 弛豫 → T2 弛豫 → 组织时间差 → 加权成像

这是对比度的答案，跟"为什么慢"无关，而且标着 **96% 置信度**。第 2 题（扫描敲击声）、第 5 题（起搏器禁忌）同样中招。

根因：`matchSeed` 用 `q.includes("核磁")` 匹配，**设备名被当成了核心关键词**。

修复：种子关键词拆成 `core`（机制级术语）与 `context`（设备名等宽泛词），context 只参与排序，**绝不单独触发匹配**。

**模型对比数据（实测）**

| | deepseek-chat | deepseek-reasoner |
| --- | --- | --- |
| 平均耗时 | 6 秒 | 24 秒 |
| 因果链深度 | 好 | 更深 |
| 坑 | 无 | `max_tokens` 必须给到 8000，否则推理 token 吃光预算，JSON 截断 |

决策：不做二选一，做成**主模型优先 + 结构验收 + 不合格自动升级**。

## 阶段 4｜20 题批量审计，抓出伪科普

**时间**：2026-10-30 12:29 – 12:48

**阶段目标**
用真实问法验证系统敢不敢让评委随便问。

**当时的做法**
写 `scripts/batch-audit.mjs`，把 20 道真实问法灌进流水线，输出逐题明细供人工核对。

结果：20/20 结构全过，但**内容上抓到一个伪科普**。

题目埋了未证实前提："为什么猫会发出呼噜声，**而且频率恰好能疗伤**？"
系统输出：「**不是**情绪表达，**而是**骨骼在借振动自我修复」，并把「骨组织修复」放进因果链，旁白说"成骨细胞开始加班"。

三层问题：把未证实说法当结论 / 为容纳边缘假说**否定主流解释** / hedge 写了争议但论点仍是断言。

**修复与验证**
prompt 加第 10 条硬约束后，同题输出变为「常被说成呼噜声能疗伤，但更可靠的说法是它源于喉部肌肉的节律振动」。

**同批次修掉的三个自身缺陷**

| 缺陷 | 现象 | 修复 |
| --- | --- | --- |
| R7 规则误报 6/20 | 把「不是…而是」判成过度断言，而这个句式是中文科普的标准修辞 | 收窄为只抓「必然/绝对/科学证明/唯一」 |
| R6 中文歧义 | 「拉开**一定**角度」被判成绝对化用语 | 正则做否定前置排除：`一定(?!的\|角度\|程度…)` |
| R5 抓到因果环 | 旧书气味题 5 节点 5 边必然成环，分镜排不出顺序 | 生成端加 `hasCycle()` 验收，失败则升级模型，仍失败则降级交付并由 R5 标红 |

## 阶段 5｜把"卖点"做成看得见的交互（原句解构）

**时间**：2026-10-30 12:48 – 13:10

**阶段目标**
用户明确主卖点是「自然语言转化为可以被科普的概念」。但第 02 步当时展示的是**转化的结果**（一张因果图），
不是**转化的动作**——评委看到的是一张漂亮的图，感受不到"一句话被拆开"。

**当时的做法**
给每个概念加 `sourceQuote` 字段：这个概念是从用户原话的哪几个字推出来的，**必须能逐字在问题里找到**。
前端把原句按这些片段切分并高亮，悬停任意概念卡，原句里对应的字就亮起来。

```
为什么【明明赢了】还想玩，直到【输光】
        ↓ 损失厌恶        ↓ 追损
```

再加一行统计：`15 字 → 6 个概念 → 6 条因果边`，把"抽象"这件事量化出来。

**过程中的三次自我否决**

| 否决的做法 | 理由 |
| --- | --- |
| 让模型自由写"出处" | 它会改写、会造句。改为服务端校验：片段必须逐字存在于问题中，找不到就留空，**不做模糊匹配，不替模型圆谎** |
| 短问题就不高亮 | 试过，反而更差。短问题里"一句话炸出 5 个概念"本身就是抽象的证据，应该展示而不是藏起来 |
| 所有概念必须指向不同片段 | 过度约束导致模型全部留空。改为"尽量不同，允许共用，但不许留空" |

**顺手补的防护**
种子库弱命中（置信度 < 0.8）时，界面弹出提示：「这次只对上了一个机制词，概念未必真的答到了你的问题，请对照原句解构看一眼」。
这条来自上一阶段那次"问 MRI 为什么慢却答成 T1/T2"的事故。

## 阶段 6｜第二步的重点：观众预演

**时间**：2026-10-30 13:04 – 13:40

**阶段目标**
用户指出：六步里第二步最重要，而当时第二步回答的是**知识**，不是**观众**。
「能回复专业知识」这件事直接问 AI 也能做到，构不成差异化。

**当时的做法：让系统扮演一个观众**
第二步新增「观众预演」：扮演一个只有大众常识的观众，把整条脚本听一遍，
逐镜报告理解程度、卡在哪里、缺了哪个前置概念、怎么补。

刻意做成**两条互不混合的通道**：

| 通道 | 内容 | 可信度 |
| --- | --- | --- |
| 规则判定（零模型调用） | 提前引用 / 数量对不上 / 开场过载，三条纯算法检查 | 硬证据，跑两次结果一致 |
| 模型估计 | 逐镜理解度、观众疑问、修补处方 | 主观估计，UI 上必须标明 |

不把两者合成一个分数，是因为一旦混了，评委追问「这个百分比怎么来的」就答不上来。

**实测（赌徒案例，6 概念 8 镜）**

- 规则判定 1 处：第 1 镜「数量对不上：说了『三套』，图里有 6 个概念」
- 模型估计 1 处：第 6 镜「『变率强化』这个词没听过，一下没接住」

两条都是真问题，而且都不是前面 7 条规则能发现的。

**过程中的自我否决**

| 否决的做法 | 理由 |
| --- | --- |
| 观众模拟自动跑 | 会让主流程从 6 秒变成 14 秒。改成按钮，主流程不变快，点击本身还成了一个演示动作 |
| 把两通道合并成一个「可理解性得分」 | 混了来源就说不清可信度，而且一旦被追问会很像编的 |
| 确定性通道只做「提前引用」 | 试跑发现它在拓扑有序的图上几乎永不触发，等于摆设。补了数量检查和开场过载检查 |
| 「三套机制」在开场/第7镜/收尾各报一次 | 同一说法重复报三次是噪音，按原文去重只报第一次 |

**演示台词（可直接背）**
> 这是系统模拟的一个普通观众。他在第 6 个镜头卡住了——我们把「变率强化」打在屏幕上，但旁白从来没解释过这个词。
> 这条提示不是模型猜的，是算出来的：屏幕上出现了术语，旁白里没有它。

**追加：把它做到底（同日 13:19 – 13:45）**

用户提出「辅助改进提示词」这半句后，我意识到之前只做了一半——能指出卡点，但用户还得自己回去改、自己重跑、自己判断有没有变好。
于是补了三件事：

1. **处方可执行**：每个卡点附一句改写好的旁白原文，点「采用处方」直接替换
2. **改完自动重演**：曲线、检查报告全部刷新，**改进前的曲线以灰色虚线留在图上**
3. **提升为独立一步**：从第二步底部的一个面板，变成第 03 步整屏。六步变七步

第 3 条是关键。你看着那条虚线被实线顶上去的那一刻，才是这个产品真正的核心。

**这一轮抓到的收敛 bug（值得记）**
「三套机制」的确定性改写是把「三套」替换成「其中三套」。但替换完之后规则**还是会再报一次**——
它只看到「三套」和 6 个概念。如果「采用处方」点完卡点还在，这个演示就崩了。
补了两道豁免：① 前面是「其中」时不再报（已经明说是子集了）；② 同一句里已点了两个概念名时不再报。
实测：第 1 镜采纳后该处消失，卡点移到第 7 镜（那里还留着一次），再采纳一次才干净——一次修一个，不假装一键全好。

## A. 概念抽取系统提示词（节选，完整版见 `src/lib/deepseek.ts`）

```
你是知识可视化编辑。你的任务不是写科普文案，而是把一个日常困惑拆成一张可拍摄的概念因果图。

硬性规则，违反任意一条即为不合格：
1. nodes 恰好 5 个或 6 个。
2. edges 不少于 nodes 数量减一，且必须构成连通图。
3. 图必须是一条自起点向终点推进的因果链，不允许出现环。
...
9. 如果该现象的主流解释本身存在学术争议，thesis 与 mechanism 必须写成
   「目前认为」「主流解释是」，不得断言单一机制，并在 hedge 字段写明争议点。
10.【最重要】用户的问题里可能埋着未经验证的说法…
   不得为了容纳一个边缘假说而否定主流解释。若主流认为是 A、边缘假说是 B，
   只能写「主流认为是 A，B 仍缺乏证据」；绝对禁止写成「不是 A，而是 B」。
```

**演进过程**：第一版只有 6 条规则 → 加入 7/8 条（禁止编造术语、绝对化表述）→ 加入第 9 条（争议需限定）→ 加入第 10 条（禁止顺着错误前提构建因果链）。
第 10 条是在 20 题审计之后补的，触发案例就是"猫呼噜疗伤"。

## B. 赛题分析阶段的追问

```
你答的 5 条里，第 2 条其实是"我还没想好"，第 3 条把我要的设计改了一半。
```

对应产出：把"三种叙事方案差异"从**叙事结构差异**改为**视觉规格差异**，
因为用户明确要求"差异化更希望是画面的风格差异"。

## C. 对"是否套壳"这一问题的判断

```
套壳的根因是 用户输入 → LLM → 直接输出成品。
只要中间有可编辑、可持久化、可复现的结构化产物，它就不是套壳。
```

对应产出：五层流水线设计 + 三个物证（可编辑中间态 / 规则引擎检查 / 算法推导分镜）。

## 阶段 8｜用 taste-skill 重做首页

**时间**：2026-10-30 19:35 – 20:10

**阶段目标**
首页从「深色桌面 + 散落纸片」换成一套有明确艺术方向的产品页。用户要求「不要严谨，要丰富、要抓人」，
最终选择用 taste-skill 从头做，只做首页（1–7 步内页留下次，那是 app screen，另一套规则）。

**当时的做法**
用 taste-skill 的 `draw.mjs` 发三张方向牌，选 `product-performs`（产品自己表演）：
不描述功能，把产品正在干活的真实片段放进页面。首屏左侧一句话，右侧整块钴蓝舞台上是**真实因果图**，
鼠标移到任一概念，原句里推出它的那几个字亮起来。

**判断与取舍**

| 本可以 | 选了 |
| --- | --- |
| 用方向单发的 Stack Sans / Albert Sans | 两者都没有中文字形，会整页回落。改用系统内确定存在的 Microsoft YaHei，保留「轻字重、大字」 |
| 用图库里的真实照片 | 四个开源图库全部连不通。按家规的优先顺序取第二档：生成两张，裁掉水印 |
| 用「客户 logo 一行」作证明 | 我们没有客户也没有 logo，家规禁止画替代品。改成自己真实测过的四个数字 |
| 页面上的数字随手写几个 | 全部从 `src/lib/demo-case.json` 读，那是一次真实编译的输出，镜号、旁白、检查项都对得上 |

**过程中抓到的真 bug（值得记）**

第 1 轮检查器报「字体没加载、首屏没有按钮」。我一开始当成字体问题去换字体栈，换了没用。
真正的原因是 **CSS 优先级**：`globals.css` 里有一条 `h1 { font-family: 宋体 }` 和一条 `.lg button { background: none }`，
它们的优先级高于我写的组件类，于是整页中文落成宋体、所有按钮变成没有底色的纯文字。
把重置全部改成 `:where()` 之后一起解决。**教训：在既有项目里写新样式，重置必须用 `:where()`。**

第二个：检查器说「只有 1 个元素在动」，但页面上明明有标题上浮。读它的源码才发现，
它数的是 `animationstart` / `transitionrun` / 内联 `style` 变化，而我的视差是靠 CSS 变量传值，不在它的正则里。
改成直接写内联 `transform` 之后，从 1 个变成 9 个。
