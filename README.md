# VIZLAB · 知识可视化编译台

把一个模糊的日常困惑，编译成一张概念因果图，再推导成一份可以直接交给任何 AI 视频工具执行的制作方案，并把执行结果收回来。

**它不生成视频。** 这不是能力缺失，是产品边界。

---

## 一句话定位

VIZLAB 是**知识可视化编译层**：编译器不执行程序，但没人说编译器是套壳。

- 输入：一句自然语言困惑，例如「为什么明明赢了还想玩，直到输光」
- 输出：概念图 → 视觉方案 → 逐镜制作规格（交接包）→ 作品档案与执行回执

## 它做什么 / 不做什么

| 做 | 不做 |
| --- | --- |
| 把困惑抽象成带因果关系的概念图 | 不调用任何视频生成模型 |
| 按视觉规格推导分镜与时长 | 不声称接入了某个视频模型 |
| 用确定性规则做方案检查 | 不做「一个输入框 + 一段长文本」的对话产品 |
| 输出可交接的制作规格并管理回执 | 不出诊断结论、不给用药方案 |

## 运行

环境要求：Node.js ≥ 20（开发使用 22.22.2）

```bash
npm install
npm run dev
```

打开 http://localhost:3000

生产模式：

```bash
npm run build
npm start
```

**不配置任何 API Key 也能完整跑通主流程**——命中概念种子库时全程零模型调用，1 毫秒出结果。

### 可选：接入模型

复制 `.env.example` 为 `.env.local`，填入 DeepSeek Key：

```
DEEPSEEK_API_KEY=sk-xxxx
```

配置后，种子库未收录的题目会走模型抽取；未配置时，系统会明确告知「尚未收录」并给出已收录方向，**不会编造内容**。

### 模型选择与自动升级

| 模型 | 平均耗时 | 特点 |
| --- | --- | --- |
| `deepseek-chat` | 约 6 秒 | 默认。结构稳定，10 题实测检查分 100、零硬伤 |
| `deepseek-reasoner` | 约 24 秒 | 因果链更深（例如把「MRI 为什么慢」推到 k 空间采样与信号平均），但需要更大的 `max_tokens`，否则推理 token 会吃光预算导致输出截断 |

流水线里做成**主模型优先 + 结构验收 + 自动升级**：
`deepseek-chat` 产出概念图后，用 `isUsableGraph()` 检查概念数、边数、连通性；任何一项不达标就用 `deepseek-reasoner` 重试一次。日常 6 秒出结果，硬题自动兜底。

### 生成端的三道闸门

模型产出的概念图要过 `isUsableGraph()` 才会被采用，检查四项：

1. 概念数 ≥ 4
2. 边数 ≥ 概念数 − 1
3. **图连通**（从起点可达全部节点）
4. **无环**（因果链一旦成环，分镜就排不出满足所有边的顺序）

任一项不过，换低温重试；仍不过则自动升级到 `deepseek-reasoner`；全部失败则**降级交付最像样的一份**，让检查引擎 R5 把它标红——不静默丢弃，也不假装成功。

### 未证实前提的处理

用户的问题里经常埋着站不住的说法：「猫呼噜的频率恰好能疗伤」「章鱼有九个大脑」「冰滑是因为压力融化」。

prompt 第 10 条硬约束要求：不得顺着这些说法构建因果链，必须写成「常被说成……但更可靠的说法是……」，且**不得为了容纳边缘假说而否定主流解释**。

### 模型路径评测

```bash
node scripts/eval-model.mjs                  # 10 题标准题库
node scripts/eval-model.mjs "为什么天是蓝的"   # 指定题目
node scripts/batch-audit.mjs                 # 批量审计 batch-questions.txt
node scripts/batch-audit.mjs my.txt          # 用自己的题库
```

`batch-audit` 会把每题的概念链、旁白、检查项写成 `scripts/out/batch-report.md`，供人工核对内容准确性——结构检查能自动化，**事实准确性必须人看**。

题库分三区：影像专业 6 题、通用科普 3 题、**争议题 1 题**（手泡水起皱——机制学界无定论，用来检验模型会不会硬下结论）。每题输出概念链、因果边数、连通性、检查分与硬伤清单。

## 五层流水线

```
L0 自然语言困惑
   ↓
L1 概念抽象        ConceptCard：学科 · 机制 · 常见误解 · 可视化抓手
   ↓              命中种子时零模型调用
L2 视觉转译        三套视觉规格（基底素材 / 色板 / 镜头语言 / 转场）
   ↓
L3 方案生成        深度分层拓扑排序 → 3 幕 → 分镜表 → 交接包
   ↓
L4 成品与质检      6 条确定性规则 → 检查报告 → 作品档案 → 执行回执
```

## 为什么它不是一个聊天框套壳

这是本项目最关键的设计约束，具体落在四件事上：

**1. 分镜是算出来的，不是写出来的。**
`src/lib/storyboard.ts` 的 `orderConcepts()` 对概念图做深度分层拓扑排序，镜头顺序、幕次划分、每镜时长全部由算法推导。同一个概念图，跑两次得到完全相同的分镜。

**2. 镜头时长由旁白字数推导。**
不是平均分配，而是「话说得多就给更多时间」，再整体拉伸到目标时长，并满足单镜 2～9 秒的上下限。

**3. 检查报告是规则引擎，零模型调用。**
`src/lib/audit.ts` 的 6 条规则全部是确定性判定：

| 编号 | 规则 | 判定依据 |
| --- | --- | --- |
| R1 | 总时长匹配 | 偏差 ≤2% 通过，≤10% 提醒 |
| R2 | 单镜节奏 | 单镜必须落在 [2s, 9s] |
| R3 | 旁白语速 | 中文舒适区 2.4～5.6 字/秒 |
| R4 | 术语落地 | 概念名必须出现在旁白或屏幕字中 |
| R5 | 结构保真 | 对任意因果边 A→B，必须 index(A) < index(B) |
| R6 | 合规扫描 | 绝对化词表 + 医疗红线词表正则匹配（「一定角度」与「一定会」分开判） |
| R7 | 争议一致性 | 内容已标注争议时，论点不得再使用「必然」「绝对」「科学证明」 |

**R5 是最有说服力的一条**：它验证的是「分镜顺序有没有背叛概念图」。模型写文案时做不到这一点，只有算法推导才能保证。

**R6 有一个中文专属的坑**：「当月亮和太阳拉开一定角度」里的「一定」是量词，不是断言。规则用正则做否定前置排除（`一定(?!的|角度|程度|范围…)`），否则每一句正常的中文科普都会被误判。

**4. 转化过程本身是可见的（原句解构）。**
`ConceptNode.sourceQuote` 记录每个概念是从用户原话的哪几个字推出来的，并且**必须逐字存在于问题中**——
服务端会校验，找不到就留空，不做模糊匹配。

前端把原句按这些片段切分高亮：悬停"沉没成本"，原句里的"还想玩"就亮起来。
这一步让评委看到的不是一张图，而是**一句话正在被拆开**。

**5. 中间产物可编辑，且下游会跟着变。**
在概念页改任意一句旁白，分镜表、每镜时长、语速检查会立刻重算。改长一句，R3 会立刻变红——这是结构化中间态存在的直接证据。
